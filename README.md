# Менеджер задач на React — лабораторная №3

Продолжение Л2: несколько списков, отдельные адреса задач, подзадачи, поиск и две темы. React 19, React Router, JavaScript, Vite. Без сторонних хранилищ состояния и библиотек компонентов.

- Репозиторий: https://github.com/heitonbg/webthirdlab
- Исходный макет: [To-Do List (Community)](https://www.figma.com/design/U09ssoBkhIpaSLmO5v0AQ7/To-Do-List-(Community)).
- [Первоначальный эскиз](docs/sketches/layout.svg) и [экраны реализации](docs/sketches/README.md).

## Запуск

Требуется Node.js 22.12 или новее (проверено на Node.js 24). Для нового клона:

```sh
git clone https://github.com/heitonbg/webthirdlab.git
cd webthirdlab
npm ci
npm run dev
```

Для уже имеющейся локальной папки перейдите в `C:\vscode\webdesignlabs\thirdlab`, затем выполните `npm install` и `npm run dev`. Откройте адрес из терминала, обычно http://localhost:5173. Открытие `index.html` двойным щелчком не поддерживается.

```sh
npm run lint       # ESLint: без ошибок и предупреждений
npm test           # 6 проверок редьюсера и хранилища
npm run build      # сборка в dist
npm run preview    # локальная проверка сборки, обычно localhost:4173
```

`node_modules`, `dist`, результаты тестов и исходная методичка не входят в Git. Зависимости фиксирует `package-lock.json`. Публикация приложения не требуется. Vite поддерживает прямые адреса и перезагрузку вложенных страниц и в dev, и в preview.

## Возможности

- Создание, переименование и удаление списков с каскадным удалением задач после подтверждения. Новый список сразу открывается. Счётчик активных задач у каждого списка.
- Добавление задач с проверкой пустого ввода, описание и необязательное время из Л2, отметка выполнения, редактирование, удаление с подтверждением, очистка выполненных и счётчик активных.
- Фильтры «Все», «Активные», «Выполненные» в URL. Прямые ссылки на список и карточку, перезагрузка, история браузера, отдельные сообщения для неверных адресов и идентификаторов.
- В карточке редактируются название, описание, время; доступны добавление, редактирование, отметка и удаление подзадач. Прогресс отображается в карточке и строке задачи.
- Поиск по названию внутри текущего списка без учёта регистра, совместно с фильтром, с задержкой 300 мс. Число результатов объявляется через `aria-live`; есть отдельное пустое состояние и сброс.
- Светлая и тёмная темы, начальная тема системы, сохранение выбора и применение до запуска React.
- Хранение данных в браузере, валидация структуры, безопасное восстановление после повреждения, миграция Л2 из `todo-app:v1` в `todo-app:v2`.
- Клавиатурное управление, видимый фокус, нативные диалоги, адаптив на 360 / 768 / 1280 px. Пользовательский текст выводится средствами JSX.

Дополнительно реализованы автоматические проверки редьюсера и браузерные проверки Playwright. Необязательные задания с перетаскиванием, сортировкой, TypeScript и третьим режимом темы не включены.

## Принятые решения

1. Отметка основной задачи независима от подзадач: можно завершить задачу с незавершёнными шагами или выполнить все шаги, оставив задачу активной. Прогресс всегда относится к подзадачам.
2. До 700 px боковая панель раскрывается кнопкой «Списки» в потоке страницы. Она не является модальным окном. Выбор списка закрывает панель; Escape закрывает её и возвращает фокус кнопке.
3. Карточка находится рядом со списком при ширине более 1100 px. На меньшей ширине она занимает область основного содержимого вместо списка; переход назад доступен вверху карточки. Общая шапка сохраняется.
4. Поиск — локальное состояние страницы списка. Он сохраняется при открытии карточки, но сбрасывается при смене списка или полной перезагрузке. Фильтр всегда хранится в URL, включая адрес карточки.
5. Название, описание и время в карточке сохраняются кнопкой «Сохранить» или Enter в однострочном поле. «Отменить ввод» и Escape восстанавливают сохранённые значения. Пустое название при потере фокуса показывает ошибку и не сохраняется. Несохранённые изменения при закрытии карточки отбрасываются.
6. Удаление списка и задачи требует подтверждения в `dialog`. Подзадачи удаляются сразу. Отмена и Escape возвращают фокус инициатору; после удаления задачи — соседней задаче или полю добавления.
7. На `/` открывается первый доступный список. При отсутствии списков показывается приглашение создать первый. Удаление текущего списка ведёт на `/`, затем в первый оставшийся список.
8. Введённые названия ограничены 200 символами, описания — 5000. Пробелы по краям удаляются. Дубликаты названий допустимы: идентичность задают UUID.
9. Миграция доступна только в том же origin браузера: протокол, хост и порт должны совпадать с Л2. Чужой origin браузер читать не позволяет. Старая запись не удаляется; существующая запись v2 имеет приоритет, в том числе пустая.
10. Если хранилище запрещено или переполнено, приложение продолжает работу в памяти и показывает предупреждение. Неверная запись v2 заменяется пустым состоянием.

## Перенос с Л2

Удалены глобальный изменяемый объект, ручная подписка `subscribe`, функция полной перерисовки, создание DOM-узлов и отдельное обновление счётчиков. Их заменяют редьюсер, контекст и JSX. Компоненты не меняют разметку через DOM API; прямые обращения к DOM используются только для темы, фокуса и нативного `dialog`.

Обработчики редактируют данные неизменяемо через `map`, `filter`, spread. Ключи элементов — идентификаторы, поэтому фильтрация и удаление не переносят состояние формы между строками. Ввод пользователя интерполируется как текст: `dangerouslySetInnerHTML` не используется. Сохранились возможности Л2 с описанием и временем, палитра и моноширинный шрифт; сами модули состояния и представления переписаны на React.

## Проверка в браузере

```sh
npx playwright install chromium
npm run test:e2e
```

Проверка собранной версии в PowerShell:

```powershell
npm run build
$env:TEST_PREVIEW = '1'
npm run test:e2e
Remove-Item Env:TEST_PREVIEW
```

В bash: `TEST_PREVIEW=1 npm run test:e2e`. Тесты сами запускают и останавливают сервер на порту 4173; освободите этот порт перед запуском. Если Chromium установлен отдельно, задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` с путём к исполняемому файлу. Для обновления иллюстраций отчёта задайте `CAPTURE_DOCS=1` перед тестами.

Проверки выполняются в отдельных браузерных контекстах и не затрагивают данные вашего обычного браузера. На 04.11.2026 ESLint, модульные тесты, сборка и браузерные сценарии проходят. Число и подробные результаты — в [таблице приёмки](docs/test-cases.md).
